# 有效车辆数据超时检查

首次实现位于 main.cpp；现已迁移至 vehicle_data_client.h/.cpp，不修改协议、模拟器和界面布局。main.cpp 通过 stateReceived 和 dataUnavailable 信号更新界面。

## 数据流

QLocalSocket → 接收缓冲 → 按换行拆包 → JSON/字段校验 → 刷新 QElapsedTimer → 更新车速和挡位。

freshnessTimer 每 100 ms 检查一次。连接正常且超过 1000 ms 未收到合法状态时，显示 -- / 车辆数据超时。检查受 GUI 事件循环调度影响，不是硬实时保证。电量 82% 仍为静态演示值，不属于当前通信数据。

- 新连接从连接成功开始计时，限制首条有效数据的等待时间。
- 完整且合法的数据才能刷新计时；收到半包或非法数据不刷新。
- 超时不关闭连接，新合法数据到达后恢复，并打印一次 Vehicle data recovered。
- 断开连接立即清除显示并使计时失效，现有两秒重连机制继续工作。
- QElapsedTimer 与日期时钟分开，不受普通系统校时影响。

## 本轮验证状态

用户已在目标板确认接收类拆分版编译成功，正常显示、断线重连、暂停超时和恢复四项依次通过。后续新增多媒体功能时，应继续确认车辆数据更新不受影响。

## 板端验收

1. 运行模拟器与新界面，确认正常收数，无重复超时提示。
2. 在前台运行模拟器的终端按 Ctrl+Z，暂停模拟器但保留连接。
3. 等待约 1～1.2 秒（正常调度下），车速应清空，显示车辆数据超时，终端出现一次 Vehicle data timeout。页面按钮和时钟继续工作。
4. 在同一个模拟器终端执行 fg，恢复发送。界面应自动恢复数字，日志出现 Vehicle data recovered，不需要重新连接。
5. 再用 Ctrl+C 退出模拟器，确认界面显示等待车辆数据并重试连接。重新启动模拟器，确认数据恢复。

Ctrl+Z 是暂停，fg 是恢复；Ctrl+C 是终止，不要混用。实验结束时不要遗留暂停的模拟器。
